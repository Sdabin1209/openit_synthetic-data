# CR-S-002: openit_link v0.1.0에 스트리밍 응답과 경로 퍼센트 인코딩 보존이 필요하다

**상태: 해소(2026-10-30). link v0.2.0이 반복자 본문, 원래 경로 매칭(%2F 보존), 405 Allow를 지원한다. 이 영역은 v0.2.0으로 올리고 겉옷을 걷어냈다.**

날짜: 2026-10-30. 보낸 곳: synthetic-data. 받는 곳: 헤드(link).

## 무엇이 부족한가
dataset-store 서버 면을 `openit_link.App/Route`로 옮기며 확인한 것(ADR 0021):
1. `Response.body`가 bytes뿐이라 데이터셋 파일·tar 다운로드를 통째로 메모리에 올린다. 이전 구현은 1MiB 청크로 흘렸다. 요청 본문도 `raw`로 통째로 읽는다(큰 게시 tar).
2. 경로 일치가 WSGI `PATH_INFO`(퍼센트 디코딩됨)를 쓴다. 계약 HTTP.md I2의 파일 경로는 `%2F`로 인코딩된 한 조각이라 `/`로 풀리면 일치하지 않는다. 이 영역은 REQUEST_URI에서 조각마다 다시 인코딩하는 겉옷을 앞에 두었다.
3. 지원하지 않는 메서드의 405에 `Allow` 머리글이 없고, 없는 경로는 인증 전에 404를 낸다(이전: 401). 계약 CONVENTIONS 9절에 이 순서가 정해져 있다면 맞는 동작이고, 아니라면 알려 달라.

## 제안
Response.body에 이터러블(바이트 청크)을 허용하고 `Route`에 경로 조각을 디코딩하지 않는 옵션(또는 REQUEST_URI 기준 일치)을 둔다.
