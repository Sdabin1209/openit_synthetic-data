# ADR 0002: 입력은 jsonl 6개이고 분할은 파일 이름으로 정한다

상태: 채택 (2026-10-28)

근거 출처 요약: 근거는 표준이 아니라 입력 형태와 계약 제약이다. 파일 이름 규칙은 `../boundary-contracts/V2_DRAFT.md`가 학습 서버에서 읽은 것으로 기록한 `lora_{a,b}_{train,val,test}.jsonl`이다(이 영역은 실제 파일을 본 적 없음).

## 맥락
게시할 입력의 모양을 정해야 한다. DatasetManifest의 files[]는 파일마다 role(LORA_A/LORA_B)과 split(TRAIN/VALIDATION/EVAL)을 하나씩 요구한다(DatasetManifest 스키마). 행에는 `split` 필드가 있다고 기록되어 있으나 그 값의 형식은 확인하지 못했다.

## 결정
입력 디렉터리(설정 `input_dir`)에서 `lora_{a,b}_{train,val,test}.jsonl` 6개를 읽는다. 하나라도 없으면 어느 파일인지 적고 종료 코드 2로 끝낸다. 분할은 파일 이름으로 정한다(train → TRAIN, val → VALIDATION, test → EVAL). 행의 `split` 값은 정보로만 센다(값은 보고서에 적지 않고 개수만).

## 왜 (따른 표준과 근거)
- 매니페스트가 파일 단위로 분할을 요구하므로 파일 이름이 가장 직접적인 대응이다.
- 행의 split 값 형식을 모르는데 그것에 의존하면 형식이 다를 때 조용히 틀린다. 파일 이름은 계약 리포 기록에서 온 값이라 추정이지만 틀리면 파일 없음 오류로 크게 실패한다.

## 검토한 대안과 버리는 이유
- 행의 `split` 필드로 분류: 값 형식을 확인하지 못해 버린다. 형식 확인 후 파일 이름과의 일치 검사를 추가할 수 있다.
- 디렉터리의 모든 jsonl을 읽기: 어떤 파일이 어떤 역할인지 추측해야 해서 버린다.

## 결과
얻는 것: 누락이 즉시 드러난다. 감수하는 것: 파일 이름이 다르면 쓸 수 없다(설정으로 이름을 바꾸는 기능은 없음). 행 형식 추정은 ADR 0003이 안전망이다.

## 되돌리는 조건
실제 파일 이름이나 행의 split 형식이 확인되어 다르거나, 데이터셋 담당이 다른 배치를 낼 때.
