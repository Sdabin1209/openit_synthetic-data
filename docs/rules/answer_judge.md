## 6. Answer Judge 규칙
항목 하나씩 아래 표대로 보낸 뒤 합친다.

1. 판정의 상태는 위에서부터 처음 맞는 것: 선행 불충족 → 선행 불충족. 모름·거절 → 모름·거절. 문제가 있으면 애매(사유 = 문제). 확인 대기 값과 같음 → 정정(받아들임). 현재 값과 같음 → 정상(확인 대기가 있으면 버림). 현재 값 없음 → 정상(의도가 정정이어도). 정정 의도 → 정정(확인 대기가 있으면 버림). 답함이고 현재 값과 다름 → 충돌(확인 대기 새로 둠). 빠진 필수 슬롯마다 누락 판정을 더한다.
   - 왜: 순서가 정해져 있어야 같은 입력에 항상 같은 판정이 나온다. 고칠 값이 없던 슬롯의 "정정"은 첫 답이다.
2. 확인 대기가 있는 슬롯에 대한 판정은 기다리는 답과 상관없이 확인 대기 처리를 함께 낸다(애매·누락 판정은 처리 없음): 확인 대기 값과 같은 값 → 받아들임(정정). 현재값과 같은 값 → 버림(정상). 정정·모름·거절 → 버림. 둘 다와 다른 새 값 → 충돌(새로 둠, 있던 것은 대체).
   - 왜: 묻지 않았어도 사용자가 스스로 정리할 수 있다. 확인 대기가 판정과 어긋난 채 남지 않게.
3. 같은 대상에 항목이 여럿이면 하나로 합친다. 값이 이긴다: 확인 항목과 값이 함께면 값으로 정한다. 값과 모름·거절이 함께면 값. 값끼리는 표준 값이 같으면 하나(정정 표지가 하나라도 있으면 정정 쪽), 다르거나 표준 값이 없는 것이 섞이면 애매(모호함, 이번에 말한 값은 " / "로 잇는다). 모름·거절끼리는 뒤의 것. 선행 불충족 판정은 합칠 때 빼고 본다. 값 판정(정상·정정·충돌·애매)이 있는 슬롯의 값 없는 정정 요청은 버린다.
   - 왜: 한 슬롯에 판정이 둘이면 저장 판단이 무엇을 할지 정할 수 없다. 값은 가장 구체적인 대답이다.
4. 확인-긍정과 확인-부정이 함께면 둘 다 무관과 같이 본다. 확인 대기 확인을 기다릴 때 그 슬롯에 값·모름·거절 판정이 있거나 문항 전체 모름·거절이 그 슬롯을 덮으면 확인 항목은 버린다.
   - 왜: 무엇에 답했는지 알 수 없다. 값이 함께 오면 값이 대답이다.
5. 문항 전체 모름·거절 판정은 같은 문항에서 슬롯 판정이 있는 슬롯을 빼고 본다(남는 슬롯이 없으면 판정 없음). 남은 슬롯 중 확인 대기가 있는 슬롯은 모두 버린다(슬롯 판정이 있는 슬롯의 확인 대기는 그 판정대로).
   - 왜: "술은 잘 모르겠는데 소주는 마셔요"에서 종류는 답이다.
6. 무효화 대상 문항: 판정이 정정·모름·거절이거나 확인 대기 받아들임인 슬롯의 문항의 영향받는 후속 문항 전부.
   - 왜: 선행 답이 바뀌면 후속 답은 더 맞지 않는다(C2). 첫 답인지는 따지지 않는다: 첫 답이면 후속 기록이 있을 수 없고(원칙 8), 기록이 없는 슬롯에는 저장 판단이 아무것도 내지 않으므로 해가 없다. 그래서 상태 판정은 현재값을 받지 않아도 된다.
7. 요청의 대상 문항 ID ← 항목의 대상. 나중에·안내인데 대상이 없으면 기다리는 답의 대상 문항(하나일 때). 대상이 정의에 없었으면 없음. 같은 요청은 합치고 원문 표현을 모은다.
   - 왜: "이건 이따 할게요"는 지금 묻는 문항이다. 정의에 없는 문항을 미룬다는 말이 지금 문항을 미루지 않게.
8. 정의에 없는 대상이 붙은 요청·위험 신호는 대상만 없는 것으로 보고 그 의도대로 다룬다.
   - 왜: 잘못 붙은 대상 때문에 직원 요청이나 위급한 말이 무관이 되면 안 된다.
