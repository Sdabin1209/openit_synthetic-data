# ADR 0001: 생성기에서 게시기로 바꾼다

상태: 채택 (2026-10-28)

근거 출처 요약: 사용자가 결정했다(G02 해소 방향). 근거 기록의 위치: 이 결정 자체는 헤드의 대장(OPEN_GAPS G02)에 있고 이 영역은 읽지 않았다(워크스페이스 규칙상 읽기 범위 밖). 이 영역이 가진 근거는 docs/STATUS.md의 기록뿐이다.

## 맥락
생성 파이프라인(시나리오 설계, 발화/응답 생성, 노이즈, 정답 구성)은 v1 내용을 만든다. 전체 시험에서 합성 샘플 6,066건이 모두 v2 스키마 위반으로 빠져 데이터셋이 게시되지 않았다(NOTHING_TO_DO, 코디네이터 지시문의 수치이며 이 영역이 재현하지는 않았다). 학습 데이터는 데이터셋 담당이 학습 서버에서 이미 만든다(docs/STATUS.md: 지시서가 '데이터 생성은 학습 서버 파이프라인이 이미 함'이라 적음).

## 결정
이 영역은 데이터를 생성하지 않고, 데이터셋 담당이 만든 최종 학습 데이터를 그대로 가져와 검증하고 게시하는 게시기(`python -m synthetic_data import`)를 둔다.

## 왜 (따른 표준과 근거)
- 정본은 데이터셋 담당의 파이프라인이다(사용자 결정). 한 사실을 한 곳에서만 쓴다는 워크스페이스 규칙(CLAUDE.md '이웃 영역의 사실을 복사하지 않는다')과 같은 방향이다: 데이터 내용의 정본이 둘이면 어긋난다.
- 이미 학습 서버에서 모델 학습에 쓰는 데이터와 게시되는 데이터가 같은 바이트이어야 재현·감사가 가능하다. 재생성은 같다는 보장이 없다.

## 검토한 대안과 버리는 이유
- 생성기를 v2로 다시 쓰기(재생성): 버린다. 학습 서버 파이프라인과 두 벌의 정본이 생기고, 같은 데이터가 나오는지 확인할 방법이 없다. 작업량도 크다(측정 안 함).
- 아무것도 안 하고 시드 샘플만 게시: 버린다. 학습 데이터 본체가 빠진다.

## 결과
실측(2026-10-28): 데이터셋 담당의 C1 최종 파일 6개(64,459행)가 게시기의 스키마 검증을 전부 통과했고 게시·재실행이 동작했다(docs/design.md 부록 A). 기존 생성 경로에서는 합성 샘플이 전부 걸러졌던 것과 대조된다. 단 의미 검사는 하지 않았다(ADR 0009).

얻는 것: 정본 하나, 코드가 작다(importer.py). 감수하는 것: 이 영역은 데이터의 내용 품질을 만들지 못하고 검증만 한다. v1 생성 코드와 보류 시험 15건이 남는다(제거 제안 CR-007).

## 되돌리는 조건
데이터셋 담당의 파이프라인이 서버 밖으로 데이터를 내보내지 못하거나, 사용자가 이 영역에 생성 책임을 다시 맡길 때.
