# ADR 0014: 잡 설정의 알 수 없는 키를 거부한다 (v1 키 호환 제거)

상태: 채택 (2026-10-28). ADR 0010의 결정 3(v1 키를 받되 무시)을 대체한다 (Supersedes 0010-3). ADR 0016이 구현을 계약 스키마 검사로 대체했다(결정의 취지인 모르는 키 거부는 유지)

## 맥락
v1 생성 경로를 제거한 뒤에도 `scenarios`, `generators`, `style_guide_version`을 받아 무시하고 보고서에 남겼다. 배포 E2E 설정이 이 키를 싣고 있었기 때문이다. deploy가 `e2e_steps.py`에서 `generators` 전송을 지운다.

## 결정
`parse_config`가 알 수 없는 최상위 키(허용 목록 `KNOWN_KEYS`)를 `ConfigError`로 거부한다. v1 키 무시 코드와 보고서 노트를 지운다.

## 왜
- 조용히 무시된 설정은 사용자가 효과가 있다고 믿게 한다. 제거된 기능의 키는 즉시 실패하는 편이 오류를 찾기 쉽다(fail fast).
- 호환은 ADR 0010이 처음부터 "배포가 설정을 고치면 지운다"고 한 임시 조치였다.

## 검토한 대안과 버리는 이유
- 계속 무시: 위 이유로 버린다.
- v1 키 세 개만 이름으로 거부: 낡은 용어를 직접 적어 막는 방식이라 새 오타나 다른 제거 키는 못 잡는다. 허용 목록이 일반적이다.

## 결과
얻는 것: 설정 오타가 실행 전에 드러난다. 감수하는 것: 새 최상위 키를 추가할 때 `KNOWN_KEYS`도 고쳐야 한다(시험이 현재 설정 예제로 확인). 아직 v1 키를 보내는 설정은 실패한다(deploy 수정 전 E2E 단계 7).

`import` 설정(`importer.py`의 `IMPORT_KNOWN_KEYS`)에도 같은 거부를 적용한다(2026-10-28 지시서 1, SD-01). 처음에는 `run`만 적용돼 오타 키가 `import`에서 조용히 무시됐다.

## 되돌리는 조건
설정 키가 자주 늘어 허용 목록 유지가 부담이 되면 JSON 스키마 검증으로 옮긴다.
