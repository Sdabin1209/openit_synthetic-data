# ADR 0005: 허용치는 설정으로 받고 기본값은 가장 엄격하다

상태: 채택 (2026-10-28)

근거 출처 요약: 근거: 사용자가 정책 값을 정하지 않았다. 코드의 기본값은 결정이 아니라 안전한 시작점이다.

## 맥락
검증에 실패한 행이 얼마나 있으면 게시할지, pending(미검수) 행과 개인정보 의심 행을 어떻게 다룰지 정해야 한다. 실제 데이터를 본 적이 없다.

## 결정
설정 `tolerance.max_invalid_rows`, `max_invalid_rate`는 필수(예시는 0)다. `max_cross_split_duplicate_inputs`는 기본 0, `max_pii_suspect_rows`는 생략 시 경고만, `pending_policy`는 기본 report(보고만). 각각 넘으면 REJECTED(종료 코드 4)로 게시하지 않고 사유별 건수를 남긴다. 파일에 통과 행이 0건이거나 분할 사이 scenario_id가 겹치면 항상 거부한다.

## 왜 (따른 표준과 근거)
- 실패 행을 조용히 버리지 않는다는 요구(작업 지시)와 '허용치를 넘으면 게시하지 않는다'는 요구를 설정 값으로 구현했다.
- 값 자체(0, 기본 report)는 근거 기록 없음. 실제 데이터의 실패율을 측정하지 않았다. 필수 값으로 둔 것은 기본값에 정책을 숨기지 않기 위해서다.
- pending 정책을 기본 report로 둔 것은 걸러낼지가 사용자 결정이라서다(CR-006 4번).

## 검토한 대안과 버리는 이유
- 코드에 고정 임계값: 버린다. 근거 없는 숫자가 정책처럼 굳는다.
- 실패 행을 모두 버리고 게시: 버린다. 데이터가 줄어드는 것이 조용히 일어난다.

## 결과
실측(2026-10-28, C1): 검증 실패율 0/64,459, pending 0, 의심 패턴 0, 같은 입력 중복 0이어서 기본값(모두 0)으로 게시됐다. 기본값이 너무 엄격해서 막는 일은 이 데이터에서는 없었다(다른 빌드는 측정 안 함).

얻는 것: 정책이 설정 파일(리포지토리에 남음)에 드러난다. 감수하는 것: 설정을 잘못 느슨하게 두면 나쁜 데이터가 게시된다. 허용치 안에서 게시해도 버린 건수가 매니페스트 ext에 남는다.

## 되돌리는 조건
실제 데이터로 실패율·중복률을 측정한 뒤, 사용자가 정책 값을 정하면 예시와 기본값을 그 값으로 갱신한다.

## 보강 (2026-10-29, 표준성 점검 B14·C4)
제목은 "기본값은 가장 엄격하다"인데 `max_pii_suspect_rows`의 기본이 '생략 = 경고만'이라 검출돼도 게시했다. 이제 기본은 0(의심 패턴 행이 하나라도 있으면 REJECTED)이다. 경고만 하려면 `tolerance.max_pii_suspect_rows: null`을 명시한다. 시드(`run`) 경로에도 같은 검사를 넣었다: 설정 `seeds.max_pii_suspect_rows`(기본 0, null = 경고만), 넘으면 `INVALID_RECORD`로 실행을 거부하고 사례 ID만 싣는다(값은 싣지 않는다, `pii.py`로 검사를 공유). 기대값의 출처: 이 ADR의 제목과 헤드 결정표 D106. 정규식은 형식 패턴일 뿐이라 이름·주소는 못 잡는다는 ADR 0007의 한계는 그대로다. 아직 엄격하지 않은 기본값: `pending_policy`는 report 그대로다(걸러낼지는 사용자 결정, CR-006 4항). 따라서 제목은 '허용치 중 개인정보 의심 패턴·분할 중복·검증 실패는 가장 엄격하다'로 읽는다.
깨지는 곳(2026-10-29 확인한 범위): 이 리포의 `tests/test_import.py::test_pii_suspect_counts_without_values`(경고만을 기본으로 가정, 고쳤다). `configs/import.example.json`·`configs/dev.job.json`은 의심 패턴이 없는 입력이라 영향 없음. 이 리포 밖: deploy의 E2E 단계가 만드는 import 설정에는 `max_pii_suspect_rows`가 없다(워크스페이스 규칙상 읽기 범위 밖인 파일을 검색으로 한 줄 보았을 뿐이며 입력 데이터는 읽지 않았다). 그 입력 데이터에 전화·이메일·주민번호 형태가 있으면 이제 REJECTED(종료 코드 4)가 된다 -- 확인하지 못함.
