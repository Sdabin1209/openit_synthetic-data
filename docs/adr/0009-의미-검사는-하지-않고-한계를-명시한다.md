# ADR 0009: 의미 검사는 하지 않고 한계를 명시한다

상태: 채택 (2026-10-28)

근거 출처 요약: 근거: 의미 검사 규칙은 `../boundary-contracts/tools/validate_dataset_v2.py`에만 있고 설치되는 패키지에 없다(코드 확인). 워크스페이스 규칙은 다른 리포지토리의 코드를 가져오지 않는다고 한다.

## 맥락
스키마로 표현하지 못하는 규칙(targets가 values의 key인지, next_item이 순서·건너뛰기 규칙에 맞는지, save 규칙)이 도구에만 있다. 게시기가 이를 확인하지 못한 채 '검증했다'고 하면 과장이다.

## 결정
게시기는 스키마 검증만 한다. 보고서와 매니페스트에 `semantic_checks.performed=false`를 적는다. 의미 검사를 패키지 함수나 turn-engine `validate_extraction`으로 제공해 달라는 변경 요청 CR-006(2항)을 냈다.

## 왜 (따른 표준과 근거)
- 복사는 규칙 위반이고, 복사본은 계약이 바뀌면 어긋난다(워크스페이스 규칙: 복사본 금지).
- 확인하지 못한 것을 확인한 것처럼 쓰지 않는다.

## 검토한 대안과 버리는 이유
- 도구 코드를 복사: 버린다(위 이유).
- 도구를 subprocess로 호출: 버린다. 다른 리포지토리의 경로에 의존하고 배포 환경에 도구가 없다.

## 결과
얻는 것: 한계가 보고서에 드러난다. 감수하는 것: 의미가 틀린 행이 게시될 수 있다(데이터셋 담당 파이프라인이 만든 데이터라는 신뢰에 기대는 부분).

## 되돌리는 조건
계약 패키지나 turn-engine이 의미 검사를 제공하면 연결하고 이 ADR을 대체하는 ADR을 쓴다.
