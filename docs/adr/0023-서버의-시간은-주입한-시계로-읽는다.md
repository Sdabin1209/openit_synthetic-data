# ADR 0023: 서버의 시간은 주입한 시계로 읽는다

## 상태
채택(2026-10-31, 헤드 지시서 U422).

## 맥락
dataset-store 서버(`components/link_dataset_store_server.py`)가 `time.monotonic()`을 직접 읽어 인증 실패 횟수 제한의 창과 종료 드레인 한도를 쟀다. 시험은 이 창을 확인하려고 실제로 기다리거나(sleep) 서버 모듈의 `time`을 바꿔 끼웠다. 실제 시간에 기대는 시험은 기계가 바쁜 정도로 결과가 갈렸다.

## 결정
`Service`는 단조 시계 함수 `clock`(`time.monotonic`과 같은 모양)을 필수 키워드 인자로 받고, 인증 실패 창과 드레인 한도(`DatasetServer`가 `svc.clock`을 쓴다)를 그 시계로 잰다. 컴포넌트는 `time`을 import하지 않는다. wiring(`wiring/service.py`)이 `clock=time.monotonic`을 넣는다. 시험은 `FakeClock`(`advance`로만 흐름)을 넣고 시간을 직접 흘린다. 와이어 형식·HTTP 응답·잡 출력은 바뀌지 않는다(기존 서버 시험 전부 통과).

## 왜
의존성 주입이 표준 관행이다(시계도 외부 자원). 컴포넌트가 바깥 자원을 인자로 받고 wiring이 실제 것을 넣는 구조는 D117(DESIGN.md 2절)과 같다. 판정은 결과(차단 여부, 창 만료 뒤 허용)이고 실제로 기다리는 시간은 0이다.

## 검토한 대안과 버리는 이유
- 전역 패치(freezegun, `monkeypatch.setattr(time, ...)`): 소켓·`Event.wait` 같은 블로킹 대기는 못 움직이고, 전역 시계를 바꿔 다른 라이브러리(waitress)까지 영향을 준다.
- 시험에서 실제로 sleep: 부하에 따라 결과가 갈린다.

## 결과
얻는 것: 부하와 무관한 같은 결과. 감수하는 것: `Service` 생성자에 필수 인자가 하나 늘었다(영역 내부). waitress 내부 시간(유휴 연결 시한 등)은 라이브러리 몫이라 시험하지 않고 넘기는 값만 확인한다. 드레인 한도가 지났을 때 서버가 포기하는 경로는 빈 채널 가짜가 번거로워 시험하지 않았다(미확인).

## 되돌리는 조건
시계가 필요한 컴포넌트가 여럿으로 늘면 공용 시계 타입을 `schemas/`로 정의한다.
