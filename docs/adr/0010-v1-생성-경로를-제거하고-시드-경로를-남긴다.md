# ADR 0010: v1 생성 경로를 제거하고 시드 경로를 남긴다

상태: 채택 (2026-10-28). 대체하는 것: 없음. ADR 0001의 '결과'에 적힌 "v1 생성 코드와 보류 시험 15건이 남는다"를 해소한다. CR-007의 제안 중 일부를 실행한다(CR-007이 제안한 `run` 전체 제거와 I1·I7 어댑터 제거는 하지 않았다, 아래).

## 맥락
- 생성 파이프라인(시나리오 설계, 발화·응답 생성기, STT 노이즈, 정답 구성)은 v1 내용을 만들어 합성 샘플이 전부 v2 스키마 위반으로 빠졌다. 그 시험 15건은 `needs_generator_v2`로 보류돼 있었다(tests/test_job.py 8, tests/test_units.py 7).
- D91: 학습 데이터는 데이터셋 담당의 최종 데이터를 가져와 검증·게시하고 재생성하지 않는다(ADR 0001, `import` 모드).
- 그러나 `run` 잡은 폐기 대상 하나가 아니다. 같은 `job.py` 안에 시드 경로(확정된 실패 사례 CONFIRMED를 읽어 `FAILURE_CASE_SEED` 샘플로 만들어 게시, 매니페스트 `seed_case_ids`로 인용)가 얽혀 있고, 배포 E2E 단계 7이 `python -m synthetic_data run`을 시드 설정으로 호출해 "새 데이터셋 버전이 사례 ID를 시드로 인용"함을 확인한다(deploy/scripts/e2e_steps.py의 `run_sd`, 읽기만 했고 수정하지 않았다).

## 결정
1. 삭제: `scenario.py`, `plans.py`, `directives.py`, `generators/`(규칙 생성기), `noise.py`, `labeler.py`, `bank.py`, `josa.py`, `rng.rng_for`, 보류 시험 15건과 생성 경로 전용 시험(합성 샘플 구성·노이즈·라벨러·시나리오 ID·생성기 교체·시나리오 단위 분할 검증을 `run` 결과로 보던 것), `tests/custom_gens.py`.
2. 남김(시드 경로): `seeds.py`(수집), `seed_samples.py`(옛 `pipeline.py`에서 시드 조립만 분리), `quality.py`, `split.py`, `package.py`, `job.py`의 읽기→시드→검사→분할→패키징→게시. `QuestionSetContext`는 `scenario.py`에 있던 것을 `context.py`로 옮겼다(패키저와 시드 조립이 쓴다).
3. `run`의 설정 키 `scenarios`, `generators`, `style_guide_version`은 받되 무시하고 `report.json` notes에 남긴다. `generator_version`은 `seed-only+job@<버전>`이다.
4. 공개 진입점은 그대로다: `python -m synthetic_data run|import`와 종료 코드, `synthetic_data.adapters:http_question_reader`/`http_failure_store`, `import_from_config`/`run_import`, `store/`(I2), `package.EXT`/`dumps_line`.

## 왜 (근거)
- D91과 ADR 0001: 합성 샘플의 정본은 데이터셋 담당의 파이프라인이다. 이 영역에 두 번째 생성기가 있으면 어긋난다. 합성 샘플이 전부 걸러지는 코드는 운영에서 쓰이지 않는데 시험·문서·유지 비용만 든다.
- 시드 경로는 E2E가 쓰는 살아 있는 기능이고 v1 생성기와 코드 의존이 없다(`seeds.py`는 `schemas`만, 시드 조립은 `rng.short_hash`만 쓴다). 얽힌 곳은 `job.py`와 `pipeline.py`의 한 파일 안뿐이라 분리가 가능했다. 지우면 다른 리포(deploy)의 E2E가 깨지는데 이 영역은 그것을 고칠 수 없다(다른 리포 수정 금지).
- 삭제하기 전에 확인한 것: `importer.py`가 가져다 쓰는 것은 `config._ID_RE`, `package.EXT`, `package.dumps_line`, `schemas`, `store`뿐이라 삭제 대상과 겹치지 않는다. 다른 리포에서 이 코드를 부르는 곳은 deploy/scripts/e2e_steps.py(`run`, `import`, adapters 두 개)와 deploy/scripts/prepare-host.sh(git archive로 소스를 복사)이고, boundary-contracts·question-authoring·ops-feedback은 영역 이름을 문자열로만 쓴다(읽기 토큰 역할 이름). 합성 샘플 생성 함수를 부르는 곳은 없었다.
- 측정(2026-10-28, 이 PC): 삭제 직전 커밋을 별도 작업 트리로 만들어 `configs/dev.job.json`(이웃은 tests/doubles.py 대역)으로 돌린 결과와 삭제 후 결과를 비교했다. 게시된 샘플 jsonl 2개의 줄 내용은 같았고(합성 샘플은 삭제 전에도 전부 걸러졌다), `generator_version` 문자열이 바뀌어 `dataset_digest`와 `content_hash`는 달랐다. 대역 데이터 한 건 비교이며 운영 데이터로 확인한 것은 아니다.

## 검토한 대안과 버리는 이유
- CR-007 그대로 `run`과 I1·I7 어댑터까지 전부 제거: 버린다. E2E 단계 7이 `run`을 시드 설정으로 호출한다. 헤드가 E2E 계획과 브리프(소비 계약 I1·I7)를 바꾸기 전에는 지울 수 없다. **열림**: 시드를 계속 이 영역의 `run`으로 둘지, 데이터셋 담당 쪽으로 옮길지는 헤드 결정이다.
- 생성 코드를 지우지 않고 보류 시험만 삭제: 버린다. 쓰이지 않는 코드를 시험 없이 남기면 되살릴 수 없는 코드가 된다.
- 보류 시험을 v2로 고쳐 되살림: 버린다. D91로 생성을 하지 않기로 했으므로 고칠 대상이 없다.
- `scenarios`·`generators` 설정 키를 오류로 거부: 버린다. 배포 E2E의 기존 설정이 아직 이 키를 싣고 있어 거부하면 단계 7이 깨진다. 무시하되 보고서에 남겨 조용히 사라지지 않게 한다. 배포가 설정을 고치면 이 호환을 지울 수 있다.

## 결과
- 얻는 것: 쓰이지 않는 v1 코드와 15건의 보류 시험이 사라진다. 코드가 읽는 사람에게 "이 영역은 시드와 게시기"로 보인다. git 기록에서 되찾을 수 있다(삭제 직전 커밋은 이 ADR의 커밋의 부모).
- 감수하는 것: 합성 샘플을 만들 수 없다(의도). `docs/design.md`의 v1 설명 절은 역사 기록으로 줄였다. `generator_version`이 바뀌어 같은 입력의 `dataset_digest`가 삭제 전과 다르다.
- 이번에 하지 않은 것(확신이 없어 남김): `regeneration.mode`(affected_only)의 문항 세트 제외 동작, 감수 샘플링(`review_sample.jsonl`), `review.per_kind` 설정. 생성용 이름이지만 시드 경로 산출물에도 닿는다. 쓰는 곳이 있는지 deploy에서 확인하지 못했다.

## 되돌리는 조건
사용자가 이 영역에 합성 생성 책임을 다시 맡길 때(ADR 0001의 되돌리는 조건과 같다). 그때는 삭제 직전 커밋의 코드를 쓰지 말고 v2 형식으로 새로 설계한다(v1 내용을 만드는 코드였다).
